## 📋 수락 기준 개요

대시보드 기능이 프로덕션 환경에 배포되기 위해 충족해야 할 모든 수락 기준과 테스트 시나리오를 정의합니다. Given-When-Then 형식으로 작성된 18개의 주요 시나리오를 포함합니다.

## ✅ 기능별 수락 기준

### 1. 우선순위 기반 장소 표시

#### AC-1.1: Must Visit 섹션 표시
**Given** 사용자가 우선순위 1-2의 장소를 5개 보유하고 있을 때
**When** 대시보드 페이지에 접속하면
**Then** Must Visit 섹션에 최대 4개의 카드가 그리드 형태로 표시되어야 한다
**And** 각 카드는 이미지, 이름, 카테고리, 지역, 우선순위 배지를 포함해야 한다
**And** "더보기" 링크가 표시되어야 한다

#### AC-1.2: Soon to Visit 리스트 표시
**Given** 사용자가 우선순위 3의 장소를 10개 보유하고 있을 때
**When** 대시보드 페이지를 스크롤하면
**Then** Soon to Visit 섹션에 최대 5개의 리스트 아이템이 표시되어야 한다
**And** 각 아이템은 컴팩트한 형태로 표시되어야 한다
**And** 전체 목록 보기 버튼이 제공되어야 한다

#### AC-1.3: 빈 상태 처리
**Given** 사용자가 등록한 장소가 하나도 없을 때
**When** 대시보드에 접속하면
**Then** 친근한 온보딩 메시지가 표시되어야 한다
**And** "첫 장소 추가하기" CTA 버튼이 제공되어야 한다
**And** 샘플 데이터를 보여주는 데모 모드 옵션이 제공되어야 한다

### 2. 통계 위젯

#### AC-2.1: 전체 통계 위젯 표시
**Given** 사용자가 50개의 장소를 등록했을 때
**When** 대시보드를 로드하면
**Then** 4개의 통계 위젯이 표시되어야 한다:
  - 전체 장소 수 (50)
  - 방문 완료 수 (예: 20)
  - 카테고리별 분포 (차트 또는 숫자)
  - 지역별 분포 (차트 또는 숫자)
**And** 각 위젯은 3초 이내에 데이터를 표시해야 한다

#### AC-2.2: 위젯 클릭 인터랙션
**Given** 통계 위젯이 표시된 상태에서
**When** 사용자가 "방문 완료" 위젯을 클릭하면
**Then** 방문 완료된 장소만 필터링된 목록 페이지로 이동해야 한다
**And** 필터 상태가 URL 파라미터에 반영되어야 한다
**And** 뒤로가기 시 대시보드로 돌아와야 한다

#### AC-2.3: 실시간 통계 업데이트
**Given** 대시보드가 열려있는 상태에서
**When** 다른 탭/기기에서 새 장소를 추가하면
**Then** 5초 이내에 통계 위젯의 숫자가 자동 업데이트되어야 한다
**And** 업데이트 시 부드러운 애니메이션이 적용되어야 한다
**And** 사용자에게 "데이터 업데이트됨" 토스트가 표시되어야 한다

### 3. 최근 활동 타임라인

#### AC-3.1: 활동 타임라인 표시
**Given** 최근 7일간 10개의 활동이 있을 때
**When** 대시보드의 최근 활동 섹션을 확인하면
**Then** 시간 역순으로 정렬된 활동 목록이 표시되어야 한다
**And** 각 활동은 아이콘, 설명, 상대 시간을 포함해야 한다
**And** 오늘/어제/날짜별로 그룹핑되어야 한다

#### AC-3.2: 활동 타입별 표시
**Given** 다양한 타입의 활동이 있을 때
**When** 타임라인을 확인하면
**Then** 각 활동 타입이 구분되어 표시되어야 한다:
  - 추가: 초록색 + 아이콘
  - 방문: 파란색 ✓ 아이콘
  - 수정: 주황색 ✏️ 아이콘
  - 평가: 노란색 ⭐ 아이콘
**And** 각 아이콘은 의미가 명확해야 한다

#### AC-3.3: 무한 스크롤
**Given** 30일간의 활동 데이터가 있을 때
**When** 타임라인을 끝까지 스크롤하면
**Then** 자동으로 다음 페이지의 활동이 로드되어야 한다
**And** 로딩 중 스피너가 표시되어야 한다
**And** 모든 활동을 로드하면 "더 이상 활동이 없습니다" 메시지가 표시되어야 한다

### 4. 빠른 액션

#### AC-4.1: FAB 버튼 표시 및 동작
**Given** 대시보드 페이지가 로드된 상태에서
**When** 화면을 확인하면
**Then** 우측 하단에 FAB 버튼이 고정 표시되어야 한다
**And** 스크롤해도 위치가 유지되어야 한다
**And** 클릭 시 45도 회전하며 메뉴가 확장되어야 한다

#### AC-4.2: Quick Add 기능
**Given** FAB 메뉴가 확장된 상태에서
**When** "빠른 추가" 옵션을 선택하면
**Then** Quick Save 모달이 표시되어야 한다
**And** URL 입력 필드가 자동 포커스되어야 한다
**And** ESC 키나 외부 클릭으로 닫을 수 있어야 한다

#### AC-4.3: Quick Search 기능
**Given** 많은 장소가 등록된 상태에서
**When** FAB에서 "빠른 검색"을 선택하면
**Then** 검색 바가 화면 상단에 슬라이드 다운되어야 한다
**And** 입력 시 실시간 자동완성이 제공되어야 한다
**And** 최근 검색어 5개가 표시되어야 한다

### 5. 반응형 및 성능

#### AC-5.1: 모바일 반응형
**Given** 모바일 기기(375px 너비)에서
**When** 대시보드를 열면
**Then** 모든 요소가 세로 레이아웃으로 재배열되어야 한다
**And** 카드가 1열로 표시되어야 한다
**And** 터치 제스처(스와이프)가 지원되어야 한다
**And** FAB 버튼 크기가 터치 친화적이어야 한다 (최소 44px)

#### AC-5.2: 태블릿 반응형
**Given** 태블릿 기기(768px-1024px)에서
**When** 대시보드를 열면
**Then** 카드가 2열 그리드로 표시되어야 한다
**And** 통계 위젯이 2x2 그리드로 표시되어야 한다
**And** 사이드바가 토글 가능해야 한다

#### AC-5.3: 초기 로딩 성능
**Given** 일반적인 네트워크 환경(4G)에서
**When** 대시보드를 처음 로드하면
**Then** 3초 이내에 첫 화면(FCP)이 표시되어야 한다
**And** 5초 이내에 완전히 인터랙티브(TTI)해야 한다
**And** 로딩 중 스켈레톤 UI가 표시되어야 한다

### 6. 에러 처리 및 엣지 케이스

#### AC-6.1: 네트워크 에러 처리
**Given** 대시보드 로딩 중
**When** 네트워크 연결이 실패하면
**Then** 사용자 친화적 에러 메시지가 표시되어야 한다
**And** "다시 시도" 버튼이 제공되어야 한다
**And** 오프라인 모드 안내가 표시되어야 한다

#### AC-6.2: 이미지 로딩 실패
**Given** 장소 카드에 이미지가 포함된 상태에서
**When** 이미지 로딩이 실패하면
**Then** 기본 플레이스홀더 이미지가 표시되어야 한다
**And** 카드 레이아웃이 깨지지 않아야 한다
**And** 이미지 재로드 옵션이 제공되어야 한다

#### AC-6.3: 대용량 데이터 처리
**Given** 사용자가 500개 이상의 장소를 보유한 경우
**When** 대시보드를 로드하면
**Then** 페이지네이션 또는 가상 스크롤이 적용되어야 한다
**And** 초기 로딩 시간이 10초를 초과하지 않아야 한다
**And** 메모리 사용량이 100MB를 초과하지 않아야 한다

## 🧪 E2E 테스트 시나리오

### Scenario 1: 신규 사용자 온보딩 플로우
```gherkin
Feature: 신규 사용자 대시보드 경험

  Scenario: 첫 방문 시 온보딩
    Given 신규 가입한 사용자로 로그인했을 때
    When 대시보드에 처음 접속하면
    Then 환영 메시지와 온보딩 가이드가 표시된다
    And "첫 장소 추가하기" 버튼이 강조 표시된다
    When "첫 장소 추가하기"를 클릭하면
    Then Quick Add 모달이 열린다
    When URL을 입력하고 저장하면
    Then 대시보드가 새로고침되고 첫 장소가 표시된다
```

### Scenario 2: 우선순위 기반 워크플로우
```gherkin
Feature: 우선순위 관리

  Scenario: 우선순위별 장소 관리
    Given 다양한 우선순위의 장소 20개가 있을 때
    When 대시보드를 열면
    Then Must Visit에 우선순위 1-2 장소만 표시된다
    When Must Visit 카드를 클릭하면
    Then 장소 상세 페이지로 이동한다
    When 우선순위를 3으로 변경하면
    Then 대시보드로 돌아가면 Soon to Visit로 이동되어 있다
```

### Scenario 3: 실시간 협업 시나리오
```gherkin
Feature: 실시간 동기화

  Scenario: 다중 디바이스 동기화
    Given 데스크탑과 모바일에서 동시 로그인한 상태
    When 모바일에서 새 장소를 추가하면
    Then 데스크탑 대시보드에 5초 이내 반영된다
    And 통계 위젯 숫자가 증가한다
    And 활동 타임라인에 새 항목이 추가된다
```
